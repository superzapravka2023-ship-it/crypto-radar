# Crypto Radar

Сервис на Python для анализа событий по альткоинам Bybit и отправки сценариев ручной торговли в личный Telegram. Он выполняет шесть ролей в одном процессе. Новости и ранние сигналы поставляют события, кошельки Hyperliquid и рынок Bybit дают наблюдения, аналитик собирает сценарий, независимый проверяющий может его отклонить. Состояние, аудит, симуляция и учёт расходов хранятся в PostgreSQL.

## Развёртывание

1. Помести содержимое этого каталога в корень приватного репозитория GitHub. Тестовый workflow запустится при пуше.
2. Создай проект Railway, добавь PostgreSQL и сервис из GitHub-репозитория. Сборка использует Dockerfile и railway.toml. Оставь одну реплику. Для бота с long polling достаточно приватного сервиса.
3. В переменных сервиса создай `DATABASE_URL` со ссылкой на переменную PostgreSQL, обычно `${{Postgres.DATABASE_URL}}`. Внеси `OPENROUTER_API_KEY` и `TELEGRAM_BOT_TOKEN` как закрытые переменные. Используй отдельного бота от BotFather и отдельный ключ OpenRouter с дневным лимитом.
4. Для привязки задай `TELEGRAM_CHAT_ID`, если он известен. Иначе сгенерируй случайный код на 24 символа или больше, например через `python -c 'import secrets; print(secrets.token_urlsafe(24))'`, сохрани в `TELEGRAM_PAIRING_CODE` и отправь в личный чат своего бота `/start <код>`. Привязка сохраняется в PostgreSQL. После привязки код можно убрать из переменных Railway.
5. Проверь `/status`, `/watchlist`, `/wallets` и `/cost`. Для первого рейтинга кошельков и накопления истории может понадобиться несколько минут. Если публичный Bybit API возвращает HTTP 403, проверь разрешённый для твоей юрисдикции URL и регион Railway по документации Bybit.

## Параметры

| Параметр | Значение на старте |
|---|---|
| `MIN_TURNOVER_USDT` | 10 000 000 по каждому рынку Bybit за скользящие 24 часа. Для более узкого отбора задай 15 000 000. |
| `EXCLUDED_ASSETS` | BTC, SOL, XRP, DOT исключены по базовому активу. Можно добавить другие тикеры. |
| `WALLET_COUNT`, `LIVE_WALLETS`, `WALLET_POLL_SECONDS` | 100, 10, 240. WebSocket для первых адресов. REST сверяет исполнения, включая пропуски после переподключения, с контролем веса запросов. |
| `HYPERLIQUID_ADDRESSES`, `NANSEN_API_KEY` | Список адресов имеет приоритет. Ключ подключает рейтинг Nansen. Без них сервис получает кандидатов из публичного рейтинга Hyperliquid. Этот источник используется интерфейсом площадки и может измениться. |
| `NEWS_RSS_URLS`, `CRYPTOPANIC_API_KEY`, `X_API_BEARER_TOKEN`, `X_RECENT_QUERY` | Bybit и RSS включены на старте. CryptoPanic и X подключаются при наличии соответствующих переменных. Укажи URL CryptoPanic для своего тарифа. X лучше ограничить аккаунтами, которым доверяешь, и запросом небольшой ширины. |
| `DAILY_OPENROUTER_USD` | 3 USD по UTC. Сервис резервирует расходы до вызова и сверяет стоимость с ответом API. Для таймаутов с неопределённым результатом резерв остаётся до конца суток. |
| `MAX_SPREAD_BPS`, `PAPER_SPOT_FEE_BPS`, `PAPER_PERP_FEE_BPS` | 35, 10, 5,5. Измени модель комиссий под свой тариф. Спред влияет на идеи и симуляцию. Список рынков формируется по обороту. |

Радар использует GPT-6 Luna для первичного разбора, GPT-6.2 Sol для сценария и Claude Sonnet 5.5 для независимой проверки. Сценарии формируются по свежей котировке и закрытым 15-минутным свечам. В Telegram приходят только идеи, одобренные проверяющим. Кнопка «Почему?» показывает источники и решения. `/history` включает отклонённые и истёкшие события. В 20:00 UTC бот отправляет краткую сводку.

Для Hyperliquid используются публичные адреса и доступное 7-дневное окно исполнений и funding. Рейтинг и симуляция показывают наблюдаемые результаты. Симуляция использует периодические bid/ask, оценку комиссий и funding и условное закрытие половины на первой цели. На быстром рынке промежуточные касания могут остаться между снимками. Торговые ключи Bybit не нужны.

## Локальный запуск

Python 3.12. Установи `requirements.txt`. Для проверки без реальных ключей запусти `python -m unittest discover -s tests -v`. Локальный процесс запускается командой `python -m radar.app` и по умолчанию хранит данные в SQLite. Переменные из `.env.example` нужно передать процессу через окружение. Для проверки привязки и сигналов используй отдельную конфигурацию Telegram, чтобы другой воркер не забирал обновления у рабочего бота.
